## Remaining blockers

### 1. MAJOR: status discovery and its retries can call the API inside Market Test silence

`Guard.refresh()` fetches clock, schedule, feed, then clock again at `tools/census.py:438-452`. It does not derive and install schedule windows until all four reads finish at `tools/census.py:457-468`. `Reader.public()` retries at `tools/census.py:238-248`, while only already-known `reader.quiet` windows are enforced. A delayed feed therefore crosses a silence window that the schedule response already revealed.

Offline reproduction:

- Fake time starts at `T0`.
- The schedule returned at `T0+1` reports a bench starting at `T0+1`.
- The first feed read gets 503 with `Retry-After: 130`.
- Requests are sent at offsets `0, 1, 2, 132, 133` seconds: clock, schedule, feed, feed retry, clock.
- Every request is inside the bench silence window `[T0-119, T0+601)`.
- The command eventually exits 3, but only after the prohibited calls.

Starting during an already active bench with no cache also sends four discovery calls, clock, schedule, feed, clock, before it exits 3. Existing tests at `tests/test_census.py:411-422` assert only that no card calls occur, so they miss all four status calls. The cached-window test at `tests/test_census.py:528-534` covers only the case where a prior run happened to cache the active window.

### 2. MAJOR: incomplete HTTP 200 status payloads fail open

At `tools/census.py:441-452`, non-dicts are converted to `{}`, missing `doors` is treated as open, and schedule/feed members default to empty lists. At `tools/census.py:457-468`, that incomplete data creates no windows and is marked valid for 120 seconds.

Offline reproduction:

- Clock: `{"doors": "open"}`
- Schedule: `{}`
- Feed: `{}`
- Result: exit 0 and seven card requests.

The guard must validate the status contract before granting clearance. For open doors, require an allowed `doors` value, integer tick, numeric `t_hours`, positive `tick_seconds`, schedule object with an `upcoming` list, and feed object with an `events` list. For closed doors, also require a parseable opening boundary when the scan could reach the next opening. Any incomplete or inconsistent 200 must exit 3 with zero card calls.

### 3. Product blocker: the endpoint cannot identify rival decks

The module promises "who owns every card" and "an exact snapshot of every team's deck" at `tools/census.py:1-10`. The completed guarded run returned 1,049 cards and 137 packs in 1,272 requests with no request errors, but every rival owner and rival history endpoint value was `"a team"`. Only Team 3, named dealers, and `burned` were identified.

The tally at `tools/census.py:587-612` classifies only `tNN` as a team, so all anonymized rivals collapse into one `other_owners["a team"]` bucket. The summary at `tools/census.py:863-879` cannot recover attribution. The feed remains the only observed source for rival attribution.

Repair this as a contract correction, not an attribution feature: describe the output as Team 3's exact deck plus aggregate anonymized rival circulation, rename misleading metadata and summary labels, and add a fixture containing owner `"a team"`. If rival deck attribution is still the objective, park this implementation.

## Reproduced MINOR findings

### 4. Literal credential scrubbing is incomplete

`Reader._describe()` returns `error` without `self.clean()` at `tools/census.py:227-232`. Error records persist that value at `tools/census.py:260-275`. Successful payloads use pattern-only `scrub(data)` at `tools/census.py:255-257`, so a loaded key with a nonstandard shape is not removed literally.

An offline fake key `plainfakekey987654` placed in both an error code and a successful raw payload appeared four times across emitted and persisted output. Use one recursive sanitizer for every emitted or persisted record. It must apply the shared credential patterns and literal replacement of the loaded key to keys and string values at every depth.

### 5. Default output is inside the repository

`--out` defaults to `ROOT/logs/census` at `tools/census.py:935-944`, and the module documentation repeats that boundary at `tools/census.py:38`. Parser reproduction resolves the default to the checkout's `logs/census` directory.

Require `--out`, or default to a user data directory outside the repository. Requiring it is the smallest and clearest change.

### 6. Chained top-ups overwrite an existing snapshot

`finish()` chooses the tick-derived name and only avoids equality with the immediate base at `tools/census.py:734-747`. With an original `cards-2026-10-03-t1800.json`, the first top-up writes `cards-2026-10-03-t1800-topup.json`. A second top-up based on that file chooses the original filename and overwrites it.

The offline reproduction completed both top-ups with exit 0 and changed the original census owner from `t01` to `t03`. Allocate a never-existing name, for example `-topup`, `-topup-2`, and so on, and open atomically without replacing any snapshot or history file.

## Minimal repair design

1. Narrow or park the feature based on the proven endpoint contract. Correct the module docstring, CLI help, changelog, metadata, and summary before representing this as useful rival-deck data.
2. Make local clearance a prerequisite for the first transport call. A missing, stale, malformed, or non-clear cache must exit 3 with zero calls unless the operator explicitly uses `--skip-market-check`. Store a validated `clear_until`, not only windows.
3. Enforce the last validated clearance and known windows before every request and every retry, including clock, schedule, and feed. Keep the prior clearance active during refresh. Install newly validated schedule windows immediately after the schedule response, before feed. Refuse or wait without traffic when a backoff would cross `clear_until` or a quiet-window boundary.
4. Validate complete clock, schedule, and feed schemas before advancing `valid_until`. Any malformed HTTP 200 fails closed.
5. Apply one recursive credential scrubber at the persistence boundary, require `--out`, and allocate collision-free top-up filenames.

The safety regression tests should assert all transport calls, not only card calls:

- no call during a schedule window discovered before a delayed feed retry;
- zero calls when startup lacks trusted local clearance;
- zero card calls for incomplete clock, schedule, or feed HTTP 200 bodies;
- no literal fake key in stdout, partials, snapshots, history, status, or metadata;
- parser refuses a missing `--out`;
- three chained same-tick top-ups preserve every prior file.
