## Remaining merge blockers

### 1. BLOCKER: page-completing cards use the bonus-inflated value

`agent/trade_desk.py:289-297` returns `/api/me/value["your_value"]` unchanged. `scan_offers` uses it directly at lines 150-158, and `page_bid_row` builds the bid ceiling from it at lines 213-218. That value includes the page-completion bonus, so the desk can pay more than the required plain sibling value.

Offline reproduction:

- API value: 218 P
- Plain sibling value: 112 P
- Listing: 150 P, fee 9 P
- Code result: `candidate`, surplus `59`
- Correct plain-value surplus: `112 - 150 - 9 = -47`

The existing test at `tests/test_trade_desk.py:194-211` explicitly expects the unsafe 215 P ceiling.

Required change: derive or load the plain sibling value for the page card and cap both purchase valuation and bid ceiling at that value. Add regression tests that reject the 150 P listing and reject ceilings above the plain value minus the margin.

### 2. BLOCKER: page-card buys and bids can break the 40 P reserve

`agent/trade_desk.py:197-199` replaces the configured 40 P reserve with `reserve_last_card`, whose default is 10 P. The bid path repeats the same exception at lines 341-342.

Offline reproduction:

- Cash: 110 P
- Purchase: 90 P plus 6 P fee
- Code selects the purchase and leaves 14 P

The existing test at `tests/test_trade_desk.py:187-191` explicitly approves leaving 14 P.

Required change: enforce at least 40 P after every purchase and after every outstanding cash commitment, including the page card. Remove or constrain `reserve_last_card` so it cannot lower the team floor. Replace the tests that approve the exception.

### 3. BLOCKER: an active Market Test loses its quiet guard after firing

`agent/trade_desk.py:279` passes only `schedule()["upcoming"]` to `in_bench_window`. Fired events disappear from `upcoming`, as documented by `tools/feed_recorder.py:75-77`. During the active window, the event is therefore absent and the desk resumes writes.

Offline reproduction: `in_bench_window([], 10.05, 30, Config())` returns `False`, even though 10.05 is inside a 16-tick Market Test that began at 10.0.

Required change: persist observed bench events through their computed end plus margin, including across process restarts, or consume an authoritative active-event source. Test the transition from upcoming to fired while the test is still running and test restart during the active window.

### 4. MAJOR: accepting a page-card listing leaves a duplicate acquisition bid open

`agent/trade_desk.py:316` detects an open bid only to suppress posting a new bid. The accept path at lines 335-340 neither cancels the existing bid nor defers the listing acceptance. It also has no stale-bid cleanup after inventory changes.

Offline reproduction: with an open 90 P bid for LAV-10, the desk accepted a 150 P LAV-10 listing and left the bid status `open`. A later fill can buy a duplicate after the first copy has completed the page.

Required change: cancel competing acquisition offers before accepting when safe and leased, defer acceptance if cancellation cannot be completed, and cancel stale bids whenever inventory shows the card is held. Cover immediate and queued acquisition states.

### 5. MAJOR: writes bypass the shared accept and listing lease

The PR does not import or construct `Lease`. It checks only the duel lock and live duel read at lines 319-320, then calls `b.accept` and `b.list_offer` directly at lines 338 and 342. This does not coordinate with other team processes. The repository contract in `agent/lease.py:1-30` requires one shared accept claim, listing quota claims, and non-retrying clients.

Offline reproduction: another `Lease` instance successfully claimed tick 500's accept slot and reported holder `dealer`; `trade_desk.one_pass` still issued `('accept', 1, None)` in that tick.

Required change: use a `Lease("trade_desk")`, claim the appropriate shared accept priority immediately before acceptance, and claim listing capacity before bid creation or cancellation. Release an accept claim only when the refusal is known not to have consumed it.

### 6. BLOCKER: SDK defaults silently retry writes in a later tick

`agent/trade_desk.py:399` constructs `Bazaar(URL, key)` with SDK defaults. `kit/bazaar_sdk.py:113-114` defaults to `wait_on_tick=True, retries=3`; lines 76-84 retry rate-limited calls and sleep to the next tick for `wait_for_tick`. The accept and list calls at `agent/trade_desk.py:338` and `342` therefore can be resent without re-reading cash, inventory, quiet state, offer state, or shared capacity.

Transport-level offline reproduction: a default `Bazaar` accept received `wait_for_tick` once and then returned success. The transport recorded two POSTs to `/api/offers/77/accept`; the client reported defaults `True, 3`.

Required change: build keyed clients with `wait_on_tick=False, retries=0` for writes. After any refusal, return to the outer loop. Before one leased send, refresh the clock, account, target offer, inventory, reserve, quiet state, and acquisition-offer state.

### 7. MAJOR: every keyed request bypasses the shared request throttle

`agent/trade_desk.py:399` uses raw `Bazaar` and `ReadOnlyBazaar` clients. No `Lease.throttle()` call exists in the file. The pass makes immediate keyed reads at lines 283, 287, 294, 308, and 319, while the 0.3-second delay at line 292 applies only to uncached value calls. This cannot enforce the repository-wide request budget described at `agent/lease.py:22-23` and implemented at lines 310-334.

Required change: route every keyed request, in both shadow and live modes, through the shared token bucket. The wrapper must cover all reads and writes rather than only value lookups.

### 8. MAJOR: value lookup swallows HTTP 429 and continues to a write

`agent/trade_desk.py:295-296` catches every `BazaarError` from `b.value` and returns `None`. This turns `rate_limited` into an unreadable-value skip instead of reaching the outer 429 backoff at lines 415-418.

Offline reproduction: the first value lookup raised `rate_limited` 429, the desk labelled that card `live value unreadable`, made a second value lookup, and accepted the second card in the same pass.

Required change: re-raise status 429 or code `rate_limited` from value and other decision-critical reads. Stop the pass so the outer loop backs off. Add a regression test that proves no later read or write happens after the first 429.
